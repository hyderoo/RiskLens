# Methodology

## Fraud risk
Confirmed fraud is the dataset label. Rates divide by labeled transactions only and show counts. Groups with fewer than 200 labeled rows are marked small-sample. Online transactions show 0.84% fraud vs 0.03% for swipe; MCC 5732 shows 8.6%. These are associations, not causes.

## Operational risk
The Exposure page turns flag counts into review volume: reviewed = flagged x review rate, hours = reviewed x minutes / 60. Recovery rate and minutes per review are user-set assumptions and the output is labeled simulated. At the validation-chosen threshold on the test period: 3,588 flagged, 371 true frauds, 1,875 missed; flagged value $396k vs $30.4k of fraud among flags.

## Model risk
- Split: temporal (train to 2016, validation 2017 to mid-2018, test 2018-07 to 2019-10).
- Models: LightGBM with isotonic calibration; logistic regression baseline (PR-AUC 0.0067, ROC-AUC 0.709). Seed 42, no tuning on test.
- Handling imbalance: negative down-sampling with weights; accuracy is not reported as a headline because a model that flags nothing is 99.8% accurate.
- Drift: PSI per feature (train vs validation/test) on the Monitoring page.
- Instability: performance varies by quarter; treat point estimates with caution.

## Risk bands
Bands cut the calibrated probability. Defaults 0.003 (medium), 0.01 (high), 0.03 (critical), adjustable in the UI. These are not industry standards.

## Recommendations
Generated by the API from computed metrics (`/api/recommendations`); each item shows the metric it comes from. None are claimed as causal.
