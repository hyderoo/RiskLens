# UI and feature re-audit, 19 October 2026

## Data and environment
The five files were recovered from the original supplied Drive archive. The warehouse was rebuilt and all 13,305,915 rows were rescored locally. Re-training reproduced the published rounded headline metrics (PR-AUC 0.0511, ROC-AUC 0.886, precision 10.3%, recall 16.5%). Model and data files remain ignored and are not distributed.

## Fixes
- Replaced the forced six-column Overview KPI strip with content-width-aware columns. Exact counts and currency amounts stay visible. Small phones use a single readable column.
- Reduced the mobile page-title size and let pagination controls wrap.
- Dense panel tables have cell spacing; the mobile Risk Scoring table scrolls inside its panel rather than merging count and currency values.
- Panel-header controls and provenance badges wrap at narrow widths. Analytics dimensions and Yes/No choices show readable labels instead of internal codes.
- Risk Scoring distributions now honor the global filters that the screen displays.
- Global filter changes reset Explorer pagination. Explicit drill-down dates/channels take priority over persisted filters; editing/clearing global filters removes the matching URL override.
- Analytics drill-downs preserve the current global context instead of silently losing filters.
- IDs reject decimals and negative values. Invalid numeric inputs hide old results instead of leaving stale rows visible.
- API filter validation rejects reversed date, amount and score ranges and returns 422 instead of a server error for out-of-bounds amounts. End dates use the exclusive next midnight, including every timestamp on the selected day.
- Requests that are disabled or superseded cannot display a late previous result. Detail drawers do not show a previous transaction while the next one loads.
- Case creation disables its button while saving. Case notes and severity controls have accessible names.
- Mobile navigation uses the shared modal component for focus management, Escape and close controls.
- Reversed monitoring PSI thresholds show a validation message rather than contradictory alert rules.

The temporary audit case was deleted.
- Printed the Reports page to a two-page A4 PDF and inspected both pages for readability and missing content. Browser print remains the export route.

## Limits
- Local Chromium is the browser target, not a hosted deployment or a real phone. Safari, Firefox and a screen-reader walkthrough are not covered.
- Case storage is single-user local SQLite, without authentication. Case history exists, but this is not a production multi-user audit system.
- Exports are limited to the stated row count. PDF uses browser print, not a server-generated PDF.
- Hour, weekday, card-brand and card-type charts do not drill down to transactions.
- Parallel production load and resource exhaustion are not certified. The full dataset needs a persistent disk and sufficient memory; see README.
- Synthetic labels, model estimates and scenarios remain distinct. No claim of real fraud prevention is made.
